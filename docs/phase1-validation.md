# Phase 1 Windows 桌面端验收

在仓库根目录运行 `pnpm install` 与 `pnpm tauri dev`。启动后新建或打开 `.story`，并在「模型设置」填写 OpenAI 兼容 Base URL 和模型 ID。通过「输入系统密钥」打开 Windows 原生凭据输入框，可按需实测模型接口。测试使用的本机模型档案已清理。

| 验收项 | 本机结果 |
| --- | --- |
| 前端构建与测试 | Vite 构建成功，3 项 TypeScript 测试通过 |
| 底座测试 | 7 项 Rust 测试通过，含实际 Windows 凭据存取、原生 HTTP 流、物理断连、事务重放、同键冲突和 UUID 调序 |
| 系统文件对话框 | 创建带中文文件名的 `.story`，主窗口正常进入写作台 |
| 写作闭环 | 本机测试服务收到两次能力探测和一次正常续写。双击只发出一次续写请求。采纳前原稿完整保留，采纳生成第二个正式修订 |
| 断流与恢复 | 主窗口显示远端结果未知并保留已收到的句子。单独保存为草稿，重载后原稿、终态和历史均保留 |
| 数据库 | SQLite 完整性校验通过，两条正式修订、一条独立草稿。成功调用记录实际 fixture 用量，断流缺失用量保存为空 |

.story 连接在 Rust 中打开并保持生命周期。为了对话框选定路径与修订、任务和事件的单事务写入，原子操作通过 rusqlite 实现。Tauri SQL 插件已注册，WebView 权限未开放通用 SQL 命令。本机模型档案和 Windows 凭据库独立于 .story 工程。

桌面端集成验收使用本机流式测试服务验证可重复的成功和断连场景。供应商真实用量、模型差异和价格校准记录在 Phase 0 实测报告中。
