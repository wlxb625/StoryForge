# Phase 2 创作内核验收

写作台默认自动推导七个场景维度。场景名称、在场人物、矛盾和手动覆写存入工程文件。多个章节可以链接同一场景，每次节拍任务按当前章节、场景版本、模型版本和生效配方冻结。每拍至多应用一个底色与两个专项技法，悲伤场景会禁用幽默技法。

Phase 1 的测试工程在 Windows 文件对话框中成功打开并升级到 schema 2，原稿、形式修订和断流草稿均保留。为支持跨章共用场景及可审计的 Prompt 版本，升级增加了 `writing_scenes` 与 `prompt_revisions` 两表。

原生窗口验收确认四个底色、八个专项技法和两个流派卡带可预览。通过本机文件导入了声明式卡带，样章提取任务返回的可编辑 Skill 经校验后写入工程。实验室的同场 A/B 产生了两份可采纳草稿，SQLite 记录显示两次调用使用完全相同的 Prompt，两份快照均指向所选场景、底色版本和提示词覆写。缺少缓存量的用量列显示为未知。此流程使用本机测试服务验证。

实际 API 风格验收使用 `gpt-6.2-sol`，同一场景只切换底色。两次请求均成功。都市轻快的 648 字样本以店主揶揄她上次错过车、两人交接票根推进。冷硬悬疑的 817 字样本以挂钟秒针、发湿的收据和店主停手的反应推进，问话转向他如何知道买票。实际发送的 Prompt、两份原文及供应商用量位于本机 `phase0-benchmark/runs/phase2-style-check/comparison.json`。
