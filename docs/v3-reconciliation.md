# StoryForge V3 冻结契约逐项复核

对照原报告《StoryForge_V3_工程架构与AI开发执行契约》第一至第七章。阶段测试只证明记录中的用例。0.1.0 对「报告要求已全部实现」的判断过早。

| 契约范围 | 0.1.0 实际情况 | 本轮补齐及验证 |
| --- | --- | --- |
| §3.1 节拍、场景、出版章节解耦 | 章节只有一个当前场景关联。切换时没有保留过去的关联 | 迁移 006 保留旧关联。同章可关联多个场景，正式修订保留场景，生成采用冻结时的场景。跨章可重用同一场景 |
| §3.2 意图、技能仲裁和轻提醒 | 意图已按启发式规则推导，路由已限制一个底色和最多两种专项。阶段目标、重复动作和回收期限未接入提醒 | 可见阶段目标加入意图推导，重复动作和作者配置的伏笔、包袱回收期限以可忽略的提醒显示。意图推导仍采用规则 |
| §3.3 流派卡带 | 生效卡带的说明和全部路标加入写作请求，可影响专项技法权重 | 可在场景选择路标，也可匹配同名的主笔可见大纲阶段。实验室能查看请求采用的卡带版本和具体路标 |
| §4.1 写作隔离与独立秘密审查 | 主笔按知情条件过滤。审查只读取一部分近期和相关事件，旧秘密可能被截掉 | 独立审查包含当前有效的受限设定、受限事实及相关知情记录，支持多场景视角范围。普通历史事实继续按相关性裁剪。超出后台安全预算时任务暂停 |
| §4.2 记忆候选 | 已有原文锚点、置信度及可撤销的自动入库。自动记录的事实默认只有旁白可见 | 高置信、无冲突、逐字引自同一视角片段且出现该角色名字的常规道具交接或移动，可进入该角色的写作上下文。其他候选仍按知情范围审核。冻结快照记录实际加入请求的事实和原文锚点 |
| §4.3 表层、语义和正史修改 | 表层修订保持同步，语义修订做 FTS5 检索。正史级别只有确认选项，正文和权威设定分别保存 | 正史保存前预览匹配章节、已确认事实和备注。正文和所选权威设定在同一个 SQLite 事务提交。设定版本冲突会阻止整个保存。语义级检索仍是候选提示，模型级后文语义复核尚未交付 |
| §4.4 三层质检与自动采纳 | 有本地硬门禁、独立的章节审查和提取、按需文学诊断。缺场景完成入口。后台会在审查之前采纳节拍 | 场景完成可审核其跨章片段。强依赖前章时等待记忆同步。后台把节拍暂存，完整候选稿审查通过后才自动生成正式修订 |
| §6 写作台及异常提示 | 一键续写、章列表和审查面板可用。缺灵感、底部连写入口、卷章场景树、文中红线与左侧四视图轨 | 加入四视图导航轨、卷章场景树、阶段路标、模型灵感、连写入口、正文红线、划选快捷操作和底部恢复条 |
| §6 全景、配方、实验室 | 关系、时间线、道具、伏笔、版本化 Prompt、A/B 和账单存在。部分操作入口缺失 | 补齐人物卡锁定、脱敏 JSON / Markdown 配方导出、配方页工程快照，以及实验室模型能力矩阵 |

## 托管与跨章验证

- 托管控制台读取工程中的运行记录，按章显示起草、审查、采纳、提取证据和同步记忆。辅助托管增加作者确认。模型返回、失败原因和请求依据可按章回看。
- 本地流式测试服务驱动桌面版连续处理 100 个短测试章节，100 个正式修订和 100 个同步状态均落盘。三个连续章节的辅助托管测试在每次确认前保持正文未写入，确认后才保存并推进。
- 测试人物把乌木钥匙交给掌柜。下一章同一视角的实际 HTTP 请求包含这条原文事实，切到另一人物后请求省略该事实。另一次测试中，审查模型返回空告警，本地受保护词检查仍让托管暂停，暂存稿未进入正式修订。
- 同场、同模型、同指令切换卡带，实际 HTTP 请求随之增加或去掉卡带与当前路标。另用同一对请求内容向 gpt-6.2-sol 做了短节拍实测，两次均返回正文。这组测试验证模型接收链路，文学表现和长期稳定性需要单独验收。

## 与 PlotPilot 对照

当前托管依赖桌面应用运行，基于作者选定的章节和阶段展开。关窗后可恢复检查点，关闭期间不继续生成。PlotPilot 的独立守护进程、从宏观规划自动派生章纲、可编辑剧情 DAG、向量语义召回和分阶段长期质量评估尚未在本项目交付。写作记忆采用 SQLite 中的设定、证据、人物知情和备注，按视角过滤并使用中文全文索引召回。重大语义冲突仍依赖模型审查与作者判定。

## 与报告仍有差距的项目

- §2 的插件职责划分仍有偏差。SQLite 的文件连接与事务使用 Rust 的 rusqlite，受控 HTTP 代理使用 reqwest。Tauri SQL 插件已注册，实际读写未迁到插件事务。没有为了贴合模块名称开放 WebView 的任意 SQL 权限。
- §5.1 的模型能力矩阵保留证据等级。流式、JSON 模式和用量已有探测。上下文长度与多模态的实测探测尚未交付。这两项按未知显示。
- §3.1 的新修订能关联多个场景。场景范围由不可变修订间的文字差分推导。跨多个场景的大幅重写缺少手工重标范围的工具，旧版本中没有记录的历史场景归属也无法事后精确恢复。
- §7 的多台纯净 Windows、真实供应商长程创作质量和由独立用户计时的 10 分钟流程仍需外部验收。发布包尚未签名。
